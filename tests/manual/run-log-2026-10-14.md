# Manual QA run log: 2026-10-14

**Tester:** Manual QA agent (station `manual-tests`)
**Build:** `frontend/` at the working-tree state of 2026-10-14. Two builds were tested:
1. **Demo build**: `npx vite build` with no `VITE_API_BASE_URL`, served with `vite preview` on :4321.
2. **HTTP build**: `VITE_API_BASE_URL=http://127.0.0.1:9/api`, served on :4322. The API was intercepted with Playwright `page.route` to return 503, a 3 s delay or canned data. This was used for FE-AC5 and the slow-network checks.

**Browser:** headless Chromium 141 (playwright-core 1.56.1, `/opt/pw-browsers/chromium-1194`), DPR 1.
**Method:** a throwaway Playwright script (scratchpad, not committed) drove all five charters. I inspected every screenshot by eye. For accessibility I used `page.accessibility.snapshot()`, a computed-style contrast calculation and Tab-order walks with `:focus-visible` checks.
**Time spent:** about 2.5 h equivalent across charters C1–C5.

## Defects

| ID | Severity | AC | Summary |
|---|---|---|---|
| D1 | **Medium** | FE-AC8 / FE-AC10 | Toggling availability drops keyboard focus to `<body>` |
| D2 | **Medium** | FE-AC10 (WCAG 4.1.3) | Search/filter result count and empty state are not announced |
| D3 | Low | FE-AC10 (WCAG 2.4.3) | Focus lost after Clear filters, Try again, and after saving a book |
| D4 | Low | FE-AC10 / FE-AC11 (enhancement) | Dark colour scheme not supported; the app forces light |
| D5 | Low | FE-AC5 (copy) | Footer claims "Connected to the catalog service." while the API is failing |
| D6 | Low | FE-AC7 (UX) | After save the whole list reloads with a full-page spinner, and the new book is not highlighted or scrolled to |
| D7 | Low (cosmetic) | FE-AC1 | Availability badges do not line up between rows, and the delete confirm shifts the badge |
| D8 | Low | FE-AC10 (WCAG 2.5.8) | "Available only" checkbox target is 20×20 px |

### D1: Toggling availability drops keyboard focus (Medium)
**Steps:** 1. Open `#/`. 2. Tab to the first "Mark on loan" button. 3. Press Enter.
**Expected:** Focus stays on the toggle (its label changes to "Mark available") so the user can carry on from there.
**Actual:** `document.activeElement` becomes `<body>` straight away and stays there after the update. In `BookRow.tsx` the button gets `disabled={busy}` while the request runs, and the browser blurs disabled elements. Chromium keeps the sequential-navigation start point, so the next Tab happens to land on the row's Delete. Screen readers, however, lose their place and announce nothing. The same thing happens on the delete-failure path.
**Suggestion:** Use `aria-disabled` and ignore clicks while busy, or restore focus to the toggle after `busy` clears.

### D2: Search and filter results are not announced (Medium)
**Steps:** 1. Use a screen reader or inspect live regions. 2. Type "zzz" in Search.
**Expected:** Something like "0 books" or "No books match your filters" is announced through `role="status"` (FE-AC10: "status messages use role=status").
**Actual:** The only live regions are the toast and the transient loading line. The `h2.results__heading` ("N books") and `[data-testid=empty-state]` are not live, so a blind user gets no feedback that the list changed.
**Suggestion:** Add `role="status"` (or `aria-live="polite"`) to a visually-hidden "N books found" message, or to the empty state.

### D3: Focus lost after Clear filters, Try again, and after saving (Low)
**Steps:** (a) Get the empty state, focus "Clear filters", press Enter. (b) Get the error state and activate "Try again". (c) Save a valid book.
**Actual:** In every case the activated control is unmounted and focus falls to `<body>`. (The delete flow handles this well by focusing the results heading. These flows should do the same.)
**Expected:** Move focus to the results heading, or to the search box for Clear filters.

### D4: No dark-mode support (Low, enhancement)
**Steps:** Emulate `prefers-color-scheme: dark`.
**Actual:** The rendering matches light mode exactly (`styles.css` sets `color-scheme: light` and has no dark media query). Compare 01 with 03, 05 and 11. It is fully legible, so this is not an AC breach. It is logged for product to decide.

### D5: Footer claims "Connected" while the API fails (Low, copy)
**Steps:** Use the HTTP build with the API returning 503.
**Actual:** The error panel says "We couldn't load the catalog." while the footer says "Connected to the catalog service." (evidence 11). The two contradict each other.
**Expected:** Neutral copy (e.g. "Using the catalog service"), or a footer that reflects the connection state.

### D6: Post-save list reload and no highlight (Low, UX)
After "Book added" the catalog remounts and shows the full "Loading books…" state before the list returns. The new book is sorted alphabetically somewhere in the list with no highlight or scroll-into-view, so on a long list the librarian cannot see the book they just added. FE-AC7 ("lists the new book") is technically met.

### D7: Badge column misaligned (Low, cosmetic)
At 1280 px the badge sits next to the action buttons, whose widths differ ("Mark on loan" vs "Mark available"), so badges drift by about 4–5 px from row to row (evidence 01). Opening the delete confirm widens the actions area and moves that row's badge about 240 px to the left (evidence 07). Suggestion: give the actions column a fixed width or use a grid column.

### D8: Checkbox target 20×20 px (Low)
The "Available only" checkbox is 20×20 px, below the 24×24 px minimum in WCAG 2.2 2.5.8. The clickable label makes up for it in practice. Suggestion: a 24 px box, or extra padding.

### Observations (not defects)
- The toast overlaps the footer text at 360 px and covers part of the last visible row at 1280 px for 4 s (evidence 07, 08, 10). It can be dismissed.
- Pressing Back or Cancel on a filled form discards the draft without a warning.
- The year input has `maxLength=4`, so a pasted " 1999 " is cut to " 199" and rejected. This is an edge case.
- The "Delete this book?" confirm text does not name the book on screen. The group's accessible name does.
