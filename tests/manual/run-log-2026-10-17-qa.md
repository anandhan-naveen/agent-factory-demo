# Manual QA run log: 2026-10-17 (QA environment)

**Tester:** Manual QA agent (station `manual-tests`)
**Target:** the deployed QA URL https://anandhan-naveen.github.io/agent-factory-demo/ (bundle `assets/index-DqIRSBPt.js`), after the deploy and smoke test passed. Demo mode: "Demo data" badge, in-browser mock API, `localStorage` key `library.demo.v1`. No local build was used.
**Since the last run (2026-10-14, local build):** 28 review findings were fixed, including D1–D8. This run re-tests every one of them and explores further.
**Browser:** headless Chromium 141 (Playwright 1.56.1, `/opt/pw-browsers`), DPR 1. Viewports 360×780 and 1280×860, light and dark `prefers-color-scheme`, plus `prefers-reduced-motion: reduce`.
**Method:** two throwaway Playwright scripts in the scratchpad (not committed). I inspected every screenshot by eye. For accessibility I used `page.accessibility.snapshot()`, live-region inspection, a computed-style contrast calculation, Tab-order walks with `:focus-visible` checks and bounding-box measurements.
**Limits of the QA environment:** demo mode makes no HTTP calls, so a 503 or a 3 s API delay cannot be injected. FE-AC5 was exercised through the one failure the demo API has: a search over 200 characters returns 400. The UI's `maxLength=200` blocks this, so the value was forced through the DOM. The loading state was captured inside the 250 ms demo latency. A slow-network feel session (C4) still needs an HTTP-mode QA deployment.
**Time spent:** about 2 h equivalent across charters C1–C5.

### D9: Toast hides the focused control at 360 px (Medium)
**Steps:** 1. Open the QA URL at 360×780. 2. Scroll so that a row's "Mark on loan" button sits in the bottom ~70 px of the viewport. 3. Focus it and press Enter.
**Expected:** The focused control stays at least partly visible (WCAG 2.4.11, AA, which FE-AC10 covers), and the user can see the badge change.
**Actual:** The fixed, full-width toast (16–344 px × 688–756 px) sits entirely over the focused button (710–750 px) and the row's badge for about 4 s (evidence 02). Keyboard users lose sight of their focus, and sighted users can't see the change they just made. At 1280 px the toast is centred and narrower but also covers part of a row (evidence 12).
**Suggestion:** Reserve bottom padding on `main` equal to the toast height while a toast is shown, or place the toast at the top on narrow screens, or scroll the focused element clear of it.

### D10: Load error shows "Validation failed" (Low)
**Steps:** On the QA URL, set the search to 201 characters (DOM-forced, because `maxLength=200` blocks typing it). In HTTP mode, any 400 from `GET /books` would do the same.
**Expected:** A plain explanation, e.g. "Your search is too long" or "Check your filters and try again". The field-level detail (`q: "Search must be 200 characters or fewer"`) is available in the error body.
**Actual:** "We couldn't load the catalog. / Validation failed / Try again" (evidence 10). Try again repeats the same failing request. The only way out is to edit the search, and the copy doesn't say so. Normal users cannot reach this on the demo build, hence Low.

### Observations (not defects)
- The delete confirm still reads "Delete this book? This can't be undone." without naming the book on screen. The group's accessible name does ("Confirm deleting X").
- Back or Cancel on a filled Add book form still discards the draft without a warning.
- The native search-field clear button (×) is the browser's default blue, which stands out from the green palette (evidence 05).
- No console errors or page errors were logged during the session.
